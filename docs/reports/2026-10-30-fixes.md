- **Forced**: `1. Bh7` from `k5rr/8/8/8/8/3B4/8/7K w` (White in check, only legal move) → board badge

**Forced vs opening book (Book wins).** `classifyMove` checks `book` first (`analysis.js:1444`),
then `_forcedAt` (`:1448`). Proven through the real classifier: `classifyMove(1,'w',false,true,…)`
returns `"book"` while `classifyMove(1,'w',false,false,…)` returns `"forced"`. It is not a corner case
either — scanning `data/book.json` (7,672 positions) found **9 book positions with exactly one legal
move**, and for **7** of them the single legal move lands on *another* book position (e.g. the
Scholar's-Mate-style position `r1b1k1nr/pppp1Qpp/1b6/nP2q3/2B1P3/8/P1PP1PPP/RNB1K2R b KQkq`, only
move `Kd8`, and the result is book): the real engine classified that forced move as **Book**
(`icons/book.svg`). **Verdict: acceptable.** Such a move is simultaneously theory and forced; Book is
already a neutral label (it never implies the player chose well), it is the pre-existing behaviour,
and it is rare. Owner may still decide otherwise (see Decisions).

**Cached / previously-saved review.** The saved analysis blob is
`{pgn, settingsKey, engineBuild, evals, bests, multipv}` — it stores **no `classif`** (confirmed by
`storedKeys` above, and `saveToLibrary` at `analysis.js:6519`). `computeDerived()` re-classifies on
every load (`analysis.js:7098`). So I crafted an "old" cache whose forced ply is *stored as `best`*,
reloaded, and the engine ran **0** new workers while the badge stayed `icons/forced.svg`. **Exactly
what happens: a previously saved review re-classifies itself and shows Forced; the old "best" value is
ignored (it was never stored).**

## Task 9 — AUDIT ONLY (no edits, no commits)

### 9a. Binaries

| file | bytes | MiB |
|---|---|---|
| `native/engine/stockfish-windows-x86-64-universal.exe` | 103,046,300 | 98.27 |
| `engine/stockfish-19-single.wasm` | 99,102,793 | 94.51 |

Both are committed to Git (in `.gitattributes` as `binary` / `-text`). The `.wasm` is also bundled in
every browser ZIP (verified present at 99,102,793 bytes in the newest chrome and firefox packages).

**GitHub limits** (docs.github.com → "About large files on GitHub" and "Git LFS billing"):

- Files > **50 MiB**: push succeeds but Git warns.
- Files > **100 MiB**: **blocked** in regular Git.
- Browser uploads: ≤ **25 MiB**.
- Recommended repo size < 1 GB (strongly < 5 GB).
- Releases: no total-size or bandwidth limit, but each asset must be under the plan's LFS max file size.
- Git LFS: max file **2 GB** (Free/Pro); Free includes **10 GiB storage + 10 GiB/month bandwidth**;
  LFS objects are not fetched by default clones and need `git-lfs`; billing counts against the repo
  owner.

Both files are under the 100 MiB hard block (98.27 / 94.51 MiB) but over the 50 MiB warning, so the
repo is legal but heavy (a clone pulls ~200 MB+ of engine bytes).

**Options for moving them to Releases**

1. **Move `engine/stockfish-19-single.wasm` (Full) to a Release and download it at runtime.**
   *Not viable for a shipped extension.* MV3 forbids remotely hosted code, and the WASM engine is
   evaluated in the page (CSP `script-src 'self' 'wasm-unsafe-eval'`); a runtime download cannot be
   executed. The only legal variant is to **drop Full from the store ZIPs** and offer it as an
   optional local install — losing the in-extension Full build. Trade-off: repo shrinks ~95 MB but a
   bundled engine disappears.
2. **Move `native/engine/stockfish-windows-x86-64-universal.exe` to a Release** (it is Windows-only,
   never in the browser ZIPs, and already distributed via `Install Native Engine.bat`). The `.bat`
   / `install.ps1` could fetch the asset and verify its pinned SHA-256 at install time.
   Trade-off: repo shrinks ~98 MB and the source snapshot stops carrying the exe; install now needs
   network and a verified download step, and the release asset must exist on the **fork** (today the
   helper download URL still points at upstream — see Decisions).
3. **Git LFS for both.** Trade-off: repo pointers stay small, but clones need `git-lfs`, LFS objects
   are excluded from source archives unless enabled, and Free's 10 GiB/month bandwidth is consumed by
   ~100 clones of the 95 MB blob — easy to exhaust. AGENTS.md already warns to prefer Releases over
   LFS.

Recommendation (not applied): (2) for the native exe is the cleanest win; keep the Full `.wasm`
bundled because MV3 cannot load it remotely.
